Signal Service Dashboard Guide

A practical manual detailing what each module is used for and step-by-step instructions on how to use it.

1. Environment Setup .env

The frontend dashboard requires only a single environment variable to route API requests and WebSocket connections to the Signal Service core backend:

.env / .env.local 
BACKEND_URL=http://localhost:4000

Configure this in your local .env file. Port 4000 is the default port of the Signal Service backend.

2. Real-Time Monitoring Module /monitoring

✦ What It Is Used For
  • Live WebSocket Testing: Test connections directly to /notifications gateway with custom Project ID & Secret without writing frontend code.
  • Real-Time Latency Tracking: View active round-trip latency (RTT in milliseconds) updated every 3 seconds and on engine handshakes.
  • Channel & Room Manager: Join rooms, verify presence, inspect active memberships, and enable Auto-rejoin across reconnects.
  • S2S Broadcast Tester: Emit test events across any scope (broadcast, project, app, room, user) using pre-built templates or custom JSON.
  • cURL Command Generator: Instantly copy cryptographically signed (HMAC-SHA256) cURL commands to test backend integrations.
  • Telemetry & Terminal Logs: Observe inbound room events, track connected client counts, filter logs by severity (ALL, INFO, WARN, ERROR, EMIT), and copy logs with 1 click.

How to Use It (Step-by-Step)

1
Connect to the WebSocket Gateway

In the Connection Control card:

  • Enter your Project ID and App ID.
  • Enter your Secret Key.
  • Choose Mode: Select Client Mode for standard testing, or Admin Mode to receive server-wide telemetry events.
  • (Optional) Toggle Auto-Reconnect to keep reconnecting if the server reboots.
  • Click Connect. The badge turns green, displaying your live Socket ID (click to copy) and active Latency (e.g. 8ms).
2
Sync Credentials & Join Subscription Rooms
  • Click "Sync to Sections" at the top right of Auth to automatically populate your Project ID and App ID into the Channel and S2S panels.
  • In Channel & Presence Manager, enter the target room name (e.g. invoices or attendance_kiosk_gate1).
  • Check "Auto-rejoin on reconnect" so your client automatically re-subscribes if the connection drops.
  • Click Join Room. Your joined room appears as a badge.
  • Pro-tip: Click the "Target" button on any active room badge to instantly copy that room name into the S2S Broadcaster.
3
Broadcast Events & Generate Signed cURL

In the Server-to-Server (S2S) Broadcaster card:

  • Select the broadcast Scope: broadcast, project, app, room, or user.
  • Enter the Target (e.g. room name or user ID) and Event Name (e.g. order_updated, student_scanned).
  • Pick a template from the Payload Preset dropdown (Notification, Invoice Created, Order Status, Heartbeat Ping) or write your own JSON.
  • Click "Format JSON" to clean and validate your payload structure.
  • Click "Dispatch S2S" to fire the event immediately, or click "Copy as cURL" to paste a pre-signed terminal command into your terminal or postman.
4
Monitor Inbound Events & Filter Logs
  • Telemetry Tabs: Switch to Client Events to monitor connect/disconnect counts, or Emit Logs to inspect broadcast history.
  • Live Terminal: Displays all incoming events received on your joined rooms in real-time (e.g., [Inbound "student_scanned"]).
  • Filter messages using the level pills: ALL INFO WARN ERROR EMIT.
  • Use "Copy Logs" to grab the entire terminal history, or toggle "Auto-scroll" to keep focus on incoming streams.

3. Project Management Module /project

✦ What It Is Used For
  • Multi-Tenant Management: Create and partition isolated projects using the Signal Service platform.
  • API Credentials Generation: Generate unique project_id identifiers and cryptographic secret_key HMAC tokens for backend systems (Laravel, Node.js, Go).
  • Secret Key Rotation: Regenerate secret keys when credentials are exposed or need scheduled security rotation.
  • Webhook Callbacks: Configure project-level webhook endpoints to receive delivery confirmation or event triggers.
  • Status Control: Instantly enable or disable a project to permit or cut off real-time traffic without code changes.

How to Use It (Step-by-Step)

1
Create a Project
  • Navigate to Projects (/project) and click "Create Project".
  • Enter a descriptive Project Name (e.g. Learning Hub).
  • (Optional) Enter your Webhook URL to receive delivery callbacks.
  • Add an optional Description and click Save.
2
Retrieve Secret Key for Backend (.env)
  • Click the Key icon on your project row.
  • Reveal and copy the unmasked Secret Key.
  • Paste the credentials into your backend (e.g. Laravel .env):
Laravel .env 
SIGNAL_HOST=http://localhost:4000
SIGNAL_PROJECT_ID=proj_your_project_id
SIGNAL_SECRET=your_project_secret_key
3
Rotate Credentials or Toggle Status
  • Rotate Secret: Click the Rotate icon on the project row to generate a new key. Update your backend .env immediately.
  • Toggle Status: Click the Status toggle to instantly activate or suspend project operations.
  • Edit / Delete: Use the Pencil icon to update project metadata or Trash icon to remove the project.

4. Device Management Module /device

✦ What It Is Used For
  • Hardware Terminal Registration: Register attendance terminals, turnstiles, and biometric devices (e.g. AiFace kiosks connecting on raw WS port 8088).
  • Serial Number (`sn`) Mapping: Bind the hardware terminal's serial number to the correct tenant Project ID and App ID.
  • Real-Time Room Routing: Define the exact WebSocket room (e.g., attendance_kiosk_gate1) that receives live scan broadcasts in Redis.
  • Event Customization: Specify the custom event name emitted to clients (e.g., student_scanned).
  • Webhook Verification Endpoint: Configure the backend webhook URL used by Signal Service to fetch scan user details if not found in Redis cache.

How to Use It (Step-by-Step)

1
Register a Physical Device

Navigate to Devices (/device) and click "Create Device". Complete the fields:

  • Device Name: e.g. Main Gate Scanner #1
  • Device ID: Internal ID e.g. 1001
  • Device Serial: Hardware serial number (sn) broadcast by the device (e.g. SN-99882-Y).
  • Project ID: Tenant project ID (e.g. proj_smart_campus).
  • App ID: Application ID (e.g. app_attendance).
  • Room: Destination room clients listen to (e.g. attendance_kiosk_gate1).
  • Event: Event name clients receive (e.g. student_scanned).
  • Webhook: Backend lookup URL (e.g. https://backend.example.com/api/v1/scan-verify).
2
Re-route Hardware Dynamically Without Rebooting

If physical hardware is relocated (e.g. moved from Gate 1 to the Library):

  • Click the Edit (Pencil) icon next to the device.
  • Change the Room to attendance_library or change the Event name.
  • Click Update.
  • The Redis route lookup table updates immediately. The physical terminal continues scanning without needing a reboot or firmware update.
3
Decommission or Retire Hardware

When replacing or taking down a hardware terminal:

  • Click the Delete (Trash) icon on the device row.
  • Confirm deletion. Signal Service will purge the Redis routing mapping for that serial number.
