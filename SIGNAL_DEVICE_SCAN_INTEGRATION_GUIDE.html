Signal Service - Hardware Device Scan & Attendance Guide

Complete integration manual for biometric terminals (fingerprint, facial recognition, RFID), raw WebSocket ingestion (:8088), Redis route lookup, user cache fallback, and instant real-time attendance monitor kiosks.

1. Architecture & Workflow Overview

The hardware integration operates via the dedicated HardwareGateway in signal-service-api (listening on raw WebSocket port 8088, path /pub/chat). It coordinates concurrently between physical terminals, Redis routing/user cache, the Laravel backend, and frontend display monitors.

1 Hardware Terminal
Terminal Connection & Standby
The hardware device connects first to Signal Service via raw WebSocket on port 8088. Signal holds the connection open and the terminal waits in standby for user scans.
ws://signal-server:8088/pub/chat
2 Hardware Terminal
User Physical Scan & Log Transmission
A user scans (face, fingerprint, or RFID). The device packages the scan record into a JSON packet and sends it over the open WebSocket.
{ cmd: "sendlog", sn: "AF8923019283", record: { user_id: "1052", verify_mode: 1, ... } }
3 Redis Cache
Route Lookup (Determine Target Room & Event)
Signal queries Redis for the device route configuration by serial number (sn) to resolve target metadata: project, application, destination room, and event name.
Redis GET device:route:{sn} → { projectId, appId, roomId, event }
4 Laravel • Redis
Scanned User Data Lookup & Cache Fallback
Signal checks Redis cache for the scanned user's profile and access status:
• Cache Hit Instantly returns cached student/employee details.
• Cache Miss Calls Laravel POST /api/student/attendance/access-scan to fetch details and access verification, then stores in Redis.
Redis: device:user:{sn}:{userId} • Fallback: POST /api/student/attendance/access-scan
5 Signal Gateway
Device Acknowledgment
Signal immediately sends an acknowledgment response back to the hardware device socket with the verification status (access: 1/0) to trigger the green chime or red buzzer.
{ cmd: "sendlog", ret: "sendlog", result: true, access: 1 }
6 Frontend Monitor
Real-Time Room Broadcast
Signal pushes the event payload to the target room subscribers (project:{projectId}:app:{appId}:room:{roomId}). Connected kiosks update the UI immediately with student photo, name, and timestamp.
socket.to("project:PROJECT_ID:app:APP_ID:room:ROOM_ID").emit("student_scanned", scanData)

2. Laravel Backend Verification API

When user details are not found in the Redis cache, signal-service-api makes a direct HTTP POST request to the Laravel backend to retrieve user data and verify access permissions.

2.1 Route Definition (routes/api.php)

PHP 
use App\Http\Controllers\StudentAttendanceController;

Route::post('/student/attendance/access-scan', [StudentAttendanceController::class, 'checkAccessScan']);

2.2 Request Contract (Signal → Laravel)

  • Method: POST
  • Endpoint: /api/student/attendance/access-scan
  • Headers:
    • Content-Type: application/json
    • X-Internal-Secret: {INTERNAL_API_SECRET}
JSON (Request Payload) 
{
  "current_date": "2026-09-14",
  "present_time": "08:30",
  "user_id": "1052",
  "user_name": "Sokha Chan"
}

2.3 Response Contract (Laravel → Signal)

Laravel must return HTTP 200 with an access flag (1 for allowed, 0 for denied) and an optional reason:

Approved Check-In Response:

JSON 
{
  "status_code": 200,
  "data": {
    "access": 1,
    "reason": "On-Time Check-In"
  }
}

Denied Access Response:

JSON 
{
  "status_code": 200,
  "data": {
    "access": 0,
    "reason": "Access Denied: Unenrolled or Suspended"
  }
}

3. Dedicated Kiosk Scan Ticket Route

Walk-through gate screens or attendance display boards operating in kiosk mode authenticate using a dedicated scan ticket endpoint without requiring user session logins:

3.1 Route Definition (routes/api.php)

PHP 
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Route;

Route::get('/scan-attendance-signal-ticket', function (Request $request) {
    // Dedicated App ID assigned for attendance display kiosks
    $appId     = '8AE496F4C88EB47721B5B202EBDBC546';
    $secret    = config('signal.signal_secret');
    $timestamp = (string) time();
    $projectId = config('signal.signal_project_id');
    $userId    = '1'; // Dedicated Kiosk / System User ID

    $signature = hash_hmac(
        'sha256',
        "{$appId}.{$timestamp}.{$projectId}.{$userId}",
        $secret
    );

    return response()->json(compact('appId', 'timestamp', 'projectId', 'userId', 'signature'));
});

4. Signal Broadcast Payload to Frontend

Once the scan is evaluated, Signal broadcasts the real-time event to the mapped attendance room:

  • Target Room: project:{projectId}:app:{appId}:room:{roomId}
  • Event Name: As configured in device routing (e.g. student_scanned)
JSON (Broadcast Event Payload) 
{
  "user_id": "1052",
  "user_name": "Sokha Chan",
  "device_sn": "AF8923019283",
  "status": "CHECK_IN",
  "reason": "On-Time Check-In",
  "verify_mode": 1,
  "current_date": "2026-09-14",
  "present_time": "08:30:15"
}

Status Reference

Status Value Meaning Recommended Action on Frontend
CHECK_IN Verified entry scan Display green student check card, play success chime
CHECK_OUT Verified exit scan (record.inout === 1) Display blue departure confirmation
ACCESS_DENIED Permission denied or lookup failed Display red alert card with rejection reason, play error buzzer

5. Frontend Client Implementation

5.1 Script Bundling (config/script_bundles.php)

For attendance kiosk screens, configure the bundle in script_bundles.php.

💡
Loading Order Recommendation: /js/signal.js should be the last file in the bundle. This ensures that all UI dialogs, date helpers, and attendance components (ScanAttendanceComponent.js) are fully loaded and defined before signal.js initializes and binds socket listeners.
PHP (config/script_bundles.php) 
// config/script_bundles.php
'attendance-script' => [
    'attr'        => 'defer',
    'single_file' => 1,
    'output_file' => '/dist/js/attendance.js',
    'files'       => [
        'https://cdn.socket.io/4.8.1/socket.io.min.js',
        '/assets/js/sweetalert2.all.min.js',
        'https://cdn.vectoraclouds.com/vsel/components/quicktoast/QuickToast.js',
        'https://cdn.vectoraclouds.com/vsel/utils/DateHelper.js',
        'https://cdn.vectoraclouds.com/vsel/components/date_time_picker/DateTimePicker.js',
        'https://cdn.vectoraclouds.com/vsel/utils/vsapi.js',
        '/js/components/formal/ScanAttendanceComponent.js',
        '/js/signal.js' // Should be at the last
    ]
]

5.2 Component Listener (ScanAttendanceComponent.js)

Initialize Signal with isScan = true. This instructs signal.js to fetch kiosk credentials from /api/scan-attendance-signal-ticket:

JavaScript (ScanAttendanceComponent.js) 
// ScanAttendanceComponent.js
async function initAttendanceMonitor(roomName) {
    // 1. Initialize Signal passing isScan = true
    await window.Signal.init([roomName], ["student_scanned"], true);

    // 2. Listen for incoming terminal scans
    window.Signal.addListener("student_scanned", roomName, (scanData) => {
        console.log("New scan received from terminal:", scanData);

        if (scanData.status === "CHECK_IN") {
            showSuccessCard({
                name: scanData.user_name,
                time: scanData.present_time,
                device: scanData.device_sn
            });
            playSuccessChime();
        } else if (scanData.status === "ACCESS_DENIED") {
            showDeniedAlert({
                name: scanData.user_name,
                reason: scanData.reason
            });
            playDeniedBuzzer();
        }
    });
}
